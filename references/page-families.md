# V1 Page Types

Page Type 只说明一页要解决的信息问题，不规定固定坐标、母版或装饰样式。

| Page Type | 主要任务 | 常见第一视觉 |
|---|---|---|
| Cover | 建立主题和发布会定位 | 产品、人物关系、品牌主张 |
| Section | 切换叙事章节 | 大标题、少量视觉暗示 |
| Hero | 宣布核心观点或价值 | 一句话、单一强视觉 |
| Product | 发布或解释产品 | 产品英雄图、局部特写 |
| Big Number | 用核心数字证明价值 | 单个或一组大数字 |
| Feature | 解释能力和用户收益 | 产品动作、场景或关系 |
| Product Launch | 发布新品、建立产品英雄地位并说明改变 | 产品实物、结构细节、真实使用关系 |
| Scenario Comparison | 在同一场景中表达前后、旧新或认知差异 | 同一空间、同一角色、对比轴和状态变化 |
| Comparison | 表达前后、旧新或差异 | 两个清楚的状态 |
| Data | 解释多组数据或证据 | 数字秩序、图表或场景证据 |
| Data Proof | 用真实数据证明价值、使用或市场信心 | 大数字、证据载体、来源关系和重点色 |
| System | 解释组成、协作或流程 | 抽象关系、分层或步骤 |
| Image-led | 用场景或摄影建立情绪和理解 | 满幅摄影、人物动作、产品关系 |
| Ending | 收束主张和留下记忆 | 产品、主张或极简画面 |

## 使用规则

- 每页只选择一个主 Page Type。
- `Feature` 只用于一般能力解释；如果页面核心是新品发布、同场景对比或数据证明，优先使用 `Product Launch`、`Scenario Comparison` 或 `Data Proof`，不要全部归入 `Feature`。
- Page Type 不等于固定 Layout，同一类型可以有不同构图。
- Deck Plan 中标记每页视觉强弱和信息密度，避免连续页面全部同构。
- Product 和包含目标产品的其他类型都必须触发产品 Reference 路由。
- 特殊页面可以说明原因，但不要为装饰创建新类型。
- Page Type 还必须配合 `Evidence Type`、`Dominant Carrier` 和 `Spatial Grammar`，否则不能进入 Prompt 编译。
