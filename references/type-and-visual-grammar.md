# Typography Contract 与视觉语法

## Typography Contract

这是跨页稳定规则，不是让 Image2 精确执行像素排版的承诺。

- 中文：苹方 / 思源黑体一类现代无衬线；英文和数字：Helvetica Neue / Arial 一类现代无衬线。
- 主标题：深石墨黑，单一主标题，不使用彩色字。
- 副标题与说明：中性灰，不使用彩色字。
- 图表数字：默认深石墨黑；必要强调可用字重、字号或留白，不用彩色标题制造层级。
- 相对层级：主标题约为副标题的 2–3 倍，副标题约为说明文字的 1.4–1.8 倍；同一 Deck 不随页随机改变比例。
- 行距：标题紧凑但不拥挤；正文和标签保持清晰呼吸；不要把多行标题压成一块黑条。
- 边距：标题和主要文字保持统一安全边距；左右、上下边距跨页稳定，不贴边、不漂移。
- 位置：遵守三种 Title Structure；文字区域大小由内容决定，但不改变角色顺序。

## Editorial Visual Grammar

图表、流程、逻辑、数据页的目标不是“做得扁平”，而是让信息关系获得一个有作者性的视觉表达。克制不等于均匀、同大小、同形状或没有空间层次。

### 1. Data / Big Number

- 用数字尺度、间距、轴线、标记和节奏建立秩序。
- 多组数据优先形成一条阅读节奏或一个空间序列，不默认拆成四张卡片；允许通过尺度、间距、基线、局部放大和密度变化建立主次。
- 图表只保留能证明结论的元素，不放装饰图标。

### 2. Process Flow

- 先判断页面是在表达“顺序执行”还是“能力结构升级”。如果是能力结构升级，不要把流程字面化成管道、河流、轨道或物流路径。
- 过程页可以用结构展开、任务编排、状态转化、空间分层或局部增殖表达变化；关系变化必须可被看见，而不只是由箭头和文字说明。
- 图标只是语义锚点，不是一排图库素材；图标要嵌入主关系，允许通过大小、位置和密度变化体现主次。
- 对“规则引擎 → 任务引擎”这类页面：左侧保持紧凑、单一、确定性的规则模块；中间出现任务编排核心；右侧以不同尺度和层级展开多个任务能力。不要生成管道、河流、轨道、箭头海洋或底部标签栏。
- 连接线、箭头和阶段标签必须服务于主路径，不铺满页面。

### 3. Logic / System Relationship

- 先确定一个关系隐喻：转化、层级、协作、汇聚、分流、环路或空间嵌套。
- 主关系必须有尺度和留白上的第一视觉，次级节点不得全部同等大小；允许轻微纸张、建筑、产品空间或精致实体层次，但不依赖玻璃和发光效果。
- 不使用透明圆环、玻璃平台、随机节点网络或多层卡片墙代替关系设计。

### 4. Icon Language

- 一页只使用一套图标语言：线性、面性或几何符号三选一。
- 图标需参与关系、方向、节奏或尺度，不单独作为装饰列表。
- 禁止混用系统图标、emoji、拟人插画和随机 3D 小物。

### 5. 创意边界

每个图表/流程/逻辑/数据页最多一个主要视觉隐喻。视觉隐喻必须能解释内容；如果只能增加装饰，就删除它。允许通过裁切、尺度、留白、非对称关系、局部放大、轻微空间层次或真实产品动作产生设计感，不依赖玻璃 UI、渐变光效和复杂材质。

## 场景与文字关系

- 场景与文字只使用：真实空间留白、明确硬裁切或完整画面叠字。
- 禁止白色渐隐、雾化过渡、软分割、羽化照片边界和人工白雾分隔。
- 文字区和摄影区必须通过真实空间、明确边界或叠加关系建立结构，不用模糊遮罩掩盖构图问题。
