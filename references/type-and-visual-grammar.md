# Typography Contract 与信息页视觉语法

本文件只负责跨页文字角色和 Data / Process / System 的表达逻辑，不包含具体项目内容或 Style Preset。

## Typography Contract

- 中文使用苹方 / 思源黑体类现代无衬线；英文和数字使用 Helvetica Neue / Arial 类现代无衬线。
- 主标题、副标题、标签保持稳定角色和相对比例；不逐页重新发明字体规则。
- 文字颜色按背景反差选择：浅底用深石墨黑与中性灰，深底用暖白与浅灰；禁止彩色标题。
- 所有文字保持正视画布、水平基线、无透视、无旋转。
- 标题默认上方居中；只有明确的左右关系才使用左右结构。

## 共同原则

- 先写一句“这页要让观众看懂什么关系”，再选择 Visual Mode。
- 每页一个主结论、一个主视觉关系、必要标签；最多三级信息层级。
- 视觉载体必须解释内容，不使用无法说明语义的雕塑、石块或抽象实体。
- 空间感只作用于背景和非文字图形；文字始终保持清晰正视。
- 克制不等于纯文字或纯平色带；设计感也不依赖玻璃、发光、粒子和复杂材质。

## Visual Modes

### Data / Big Number

- 先确定主数字或主结论，再安排支撑指标。
- 使用尺度、比例、基线、密度、局部放大或简洁图表表达真实数据关系。
- 不把无关联指标强行串成时间轴，也不默认拆成等大卡片。

### Process Flow

- 区分顺序执行、状态转化与能力升级。
- 顺序关系可用路径；能力升级优先使用结构展开、编排、分层或能力增殖。
- 箭头和连接线只服务主路径，不铺满页面。

### System Relationship

- 先把模块映射为输入、编排、决策、执行、反馈等真实功能角色。
- 用层级、路径、嵌套、汇聚或分流表达操作关系；只摆放几个有标签的形状不算系统设计。
- 背景可选择开阔抽象空间或极简真实场景，负责氛围与纵深；功能架构直接排在画布平面，不需要承载板。
- 背景必须预留自然文字安全区：低细节、稳定明暗、无强边缘；不使用蒙层、虚化或底板补救。

### Editorial Diagram / Logic

- 选择一个能解释内容的关系：对比、转化、层级、协作、汇聚、分流或环路。
- 图标只作为语义锚点，并保持一套统一语言；不使用图库图标行或随机 3D 小物。

## 场景与文字

- 文字可直接叠加在完整画面上，但背景需有真实留白和稳定反差。
- 背景保持清晰通透；禁止白色渐隐、雾化过渡、软分割和模糊遮罩。
- 避免强分割墙体、展板、牌子或为了文字而增加的承载元素。
