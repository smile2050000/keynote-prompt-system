Skill 视觉执行流程

从需求、叙事和风格开始，逐步得到可复制的 Prompt、可检查的 QA 记录，以及整页图片版 PPTX。

先记住一件事Skill 负责把需求想清楚、写清楚。图片平台负责生成图片。MCP 是可选的自动生图通道。

01

先看完整流程

它不是图片平台，而是 PPT 图片生产的总编排。先把内容、叙事、视觉规则和逐页约束整理好，再进入生图和 QA。

需求→内容简报→Storyboard→全局视觉规则→Prompt Pack→图片生成→QA→PPTX
有 MCP

规划确认后，先做健康测试，再自动调用 image_mcp_demo 生图。

没有 MCP

生成完整 Prompt Pack，复制到你选择的图片平台执行。

02

它负责什么，不负责什么

输入

支持 md、txt、html、pdf、pptx、截图或结构化需求。

规划

拆解 content-brief、storyboard、global-visual-contract 和 prompt-pack。

执行

通过 MCP 或外部图片平台生成图片，随后制作 Contact Sheet、QA 和图片版 PPTX。

!

默认不生成可编辑文字版 PPT，不替代图片平台，也不会凭空补数据、产品功能、Logo 或品牌事实。

03

安装与开始调用

在 Codex 中，把 Skill 项目放进：

~/.codex/skills/keynote-prompt-system/

目录至少包含：

keynote-prompt-system/
├── SKILL.md
├── agents/openai.yaml
└── references/

在 Codex 中

使用 $keynote-prompt-system。

没有 Codex

图片平台不需要安装这个 Skill。让有 Codex 的人先生成 Prompt Pack，再复制到外部平台。

04

完整流程会产出什么

文件作用
content-brief.md产品事实、准确文案、叙事目标和数据来源
storyboard.md每页核心信息、观众记忆、Page Type、视觉强弱和风险
global-visual-contract.md全套共享视觉规则和唯一 style_id
prompt-pack.md每页完整 Prompt、Reference、调用方式和质量约束
execution-log.md真实调用、Provider、Model、参数、输出和失败记录
qa/ 与 deck-preview.pptxContact Sheet、QA 记录和整页图片版 PPTX
05

两种生产路线

路线 A · 有 MCP

规划确认 → 最小健康测试 → image_mcp_demo 生图 → Contact Sheet → QA → PPTX。

路线 B · 没有 MCP

规划确认 → Prompt Pack → 复制到 ChatGPT 图片、Midjourney、即梦、豆包、可灵等 → 下载图片 → Contact Sheet / QA → PPTX。

外部平台的关键设置

无产品页：文生图，比例 16:9，尺寸按平台支持的 2K。

有产品页：图生图或参考图生成，上传产品 Reference。

多 Reference：分别说明每张图的用途，禁止直接拼贴。

06

只要某个流程时，怎么说

只做规划只生成 content-brief.md、storyboard.md、global-visual-contract.md、prompt-pack.md。不要调用图片工具。
只要 Prompt只生成 prompt-pack.md。每页写清准确文字、Reference、上传方式、比例、尺寸、Must Preserve、Avoid 和检查项。
只生成一页只生成第 03 页，不生成其他页面。使用完整 Prompt 和指定 Reference，不覆盖旧版本。
只做 QA图片已经生成，请不要重新生成。只输出 Contact Sheet 和 qa.md，检查文字、产品、裁切、风格和多图质量。
只封装 PPTX整页图片已经确认，请只封装图片版 PPTX。每页一张整页图片铺满，不添加原生文字。
只修一页只修正第 05 页，不重跑整套。保持全局风格、准确文字、Reference、比例和尺寸，只改变一个明确问题。
07

外部图片平台怎么用

无产品 Reference

选择文生图，粘贴对应页面完整 Prompt。比例 16:9，尺寸使用平台支持的 2K，数量 1 张。

有产品 Reference

选择图生图或参考图生成，上传产品图。产品图只用于识别产品身份、结构和材质，不复制参考图背景。

多 Reference 的写法

Reference 1：上一页最终图
用途：只继承布局、摄影尺度和视觉风格

Reference 2：产品图
用途：只识别产品身份、结构和材质

禁止：把两张图拼贴到最终画面，复制参考图文字或错误容器。
08

风格、Reference 与 QA

风格只从 references/style-presets.md 选择，一个 Deck 只激活一个 style_id。

neutral-modern-home

家用智能硬件、家庭陪伴、桌面智能屏。

nordic-urban-family

现代都市家庭、品质生活。

lavender-premium-women

女性消费、轻奢陪伴设备。

young-urban-consumer-tech

年轻消费电子、桌面设备。

✓

QA 必查：标题和副标题、文字和数字、产品身份、产品裁切、真实承托、额外 Logo 或页码、跨页风格、多图质量、边框和容器错误。

三条原则

先规划，再确认。产品页必须有 Reference。问题页定点重生，不默认全套重跑。
